# Photo to 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vendor page that turns a flower or bouquet photo into a `.glb` via free Hugging Face AI, with an in-browser matched build as fallback.

**Architecture:** Browser-only conversion. `aiProviders.js` calls Spaces with `@gradio/client`; `photoPalette.js` + `matchedModel.js` build the fallback with three.js; `PhotoTo3D.vue` drives the flow and attaches via the existing product update endpoint.

**Tech Stack:** Vue 3, three 0.182 (`GLTFExporter`), `@gradio/client@2.7.0`, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-16-photo-to-3d-design.md`

## Global Constraints

- No paid services; no backend changes.
- Photos JPG/PNG/WebP ≤ 10 MB in, resized ≤ 1024 px; attached GLB ≤ 10 MB.
- Loading states: `.bc-skeleton` + inline text, never spinners.
- Uses `--v-*` / `--bc-accent*` tokens so dark mode and theme color apply.

## Review Focus

- Quota exhausted → no second AI call, reset time shown, matched build offered (test: `classifyAiError` quota + `convertWithAI` stops).
- Space down/CORS/network → next provider, then fallback (test: provider order with failing fake).
- Photo with white background and green leaves → flower color is the petal color, not white or green (test: palette).
- Very large GLB from AI (> 10 MB) → Attach disabled with message, Download still works (UI check).
- Vendor leaves the page mid-conversion → no state update after unmount (guarded by an `alive` flag).
